내 맥미니에 AI 에이전트를 심는 법
— Keychain의 벽을 넘다

Claude Max 구독 재활용은 실패했다. 그런데 Codex OAuth라는 우회로가 있었다.

최병찬 2026.04.16 10분

200달러짜리 Claude Max 구독을 하고 있다. 매달 200달러. 적은 돈이 아니다.

그래서 생각했다. 집에 맥미니가 24시간 돌아가고 있으니까, 여기에 AI 에이전트를 하나 심어두면 어떨까. 내가 자는 동안에도 일하고, 폰에서 메시지 하나 보내면 응답하는, 나만의 AI 비서.

Hermes Agent라는 오픈소스 프로젝트가 딱 그 역할을 한다. NousResearch에서 만든, 로컬에서 돌아가는 AI 에이전트. 텔레그램이나 디스코드로 원격 제어도 된다.

문제는 하나였다. 인증.

Keychain이라는 벽

macOS의 Claude Code는 인증 정보를 Keychain에만 저장한다. 파일로 안 남긴다. 심지어 ~/.claude/.credentials.json 파일이 만들어져도, 시작할 때마다 삭제한다.

Hermes Agent는 그 파일을 읽어야 작동한다.

파일은 없고, 읽으려는 놈은 있고. 구조적으로 안 맞는 거다.

Anthropic에 이슈를 올렸더니 "not planned"으로 닫았다. 고칠 생각이 없다는 뜻이다.

4월 14일, 7가지 방법을 시도했다. 전부 실패.

  • 시도 1: OAuth 토큰 직접 발급 sk-ant-oat01... 토큰을 받았지만 Anthropic API가 "Invalid bearer token" 401
  • 시도 2-3: .env에 환경변수 설정 ANTHROPIC_TOKEN, ANTHROPIC_API_KEY 둘 다 같은 401
  • 시도 4: Hermes 자동 감지 기대 env를 비우면 자동으로 찾는다고 했지만, Mac에선 파일 자체가 없어서 실패
  • 시도 5: Keychain에서 추출 security find-generic-password → SSH에서 errSecInteractionNotAllowed (exit 36)
  • 시도 6-7: Claude Code 업데이트, 캐시 제거 OAuth client_id 버그 해결됐지만, 근본 문제는 keychain

7번의 시도 끝에 내린 결론: macOS에서 Claude Max 구독으로 Hermes를 돌리는 건 구조적으로 불가능하다.

여기서 보통은 포기한다.

질문을 바꾸다

4월 16일, 다시 이 문제를 꺼냈다. 이번에는 질문을 바꿨다.

"Claude 인증을 어떻게 뚫을까"가 아니라,

"파일로 토큰을 저장하는 다른 AI 서비스는 없을까?"

있었다. OpenAI Codex CLI.

Codex CLI는 codex login을 하면 ChatGPT 계정으로 OAuth 인증을 하고, 그 토큰을 ~/.codex/auth.json이라는 평범한 JSON 파일에 저장한다. Keychain이 아니라 파일.

Claude Code (macOS) OpenAI Codex CLI
토큰 저장 Keychain only (파일 삭제) ~/.codex/auth.json (파일)
다른 앱이 읽기 불가능 가능 (plain JSON)
Hermes 연동 구조적 불가 openai-codex provider 공식 지원
비용 Claude Max $200/월 ChatGPT Pro 구독 포함

그리고 결정적으로, Hermes Agent의 config.yaml을 열어보니 이미 거기 있었다.

# config.yaml의 provider 목록 중 "openai-codex" - OpenAI Codex (requires: hermes login --provider openai-codex)

Hermes가 공식적으로 Codex OAuth를 지원하고 있었다. 게다가 소스 코드를 뜯어보니 _import_codex_cli_tokens()라는 함수가 ~/.codex/auth.json을 직접 읽는다.

퍼즐 조각이 맞춰졌다.

5단계 연결

남은 건 실행이었다. 생각보다 단순했다.

  • 1. 맥북에서 codex login 브라우저가 열리고, ChatGPT 계정으로 OAuth 인증. "Successfully logged in"
  • 2. 토큰 파일 복사 scp ~/.codex/auth.json 맥미니:~/.codex/auth.json — 1초
  • 3. Hermes config 수정 provider: "openai-codex", model: "gpt-5.4"
  • 4. 테스트 hermes chat -q "say hello" --provider openai-codex → "Hello!"
  • 5. 확인 API 과금 없음. ChatGPT Pro 구독 재활용 확인
# 맥미니에서 실행한 최종 명령어 $ hermes chat -q "say hello in one sentence" \ --provider openai-codex \ --model gpt-5.4 -Q ╭─ ⚕ Hermes ─────────────────────╮ Hello! session_id: 20260416_142239_2e679f

4월 14일에 7번 실패했던 것이, 질문을 바꾸고 나니 5단계 만에 끝났다.

왜 이게 의미 있는가

표면적으로 보면 "AI 서비스 바꿔서 연결했네" 정도의 이야기다. 하지만 좀 더 들여다보면 구조적인 발견이 있다.

Insight

AI 구독 서비스의 인증 방식이 곧 확장성을 결정한다. Claude가 Keychain에 가둔 순간, 생태계 확장이 막혔다. Codex가 파일에 열어둔 순간, 서드파티 연동이 가능해졌다. 기술적 결정 하나가 사용자의 가능성을 열거나 닫는다.

또 하나. 이 맥미니에서 돌아가는 Hermes는 이제 내 에이전트다.

클라우드에 있는 ChatGPT나 Claude가 아니다. 내 책상 위 맥미니에 물리적으로 존재하고, 내 파일에 접근하고, 내가 만든 스킬을 실행하고, 텔레그램으로 원격 제어할 수 있는 에이전트.

매달 내는 구독료가 이 에이전트의 두뇌를 유지하는 비용이다. 추가 과금 없이.

재현 가이드

준비물

ChatGPT Pro 또는 Plus 구독, macOS 맥미니 (또는 아무 Mac), Hermes Agent 설치, OpenAI Codex CLI 설치

설치

# 1. Codex CLI 설치 (맥미니 + 맥북 둘 다) $ npm install -g @openai/codex # 2. 맥북에서 로그인 (브라우저 필요 — 1회만) $ codex login Successfully logged in # 3. 토큰을 맥미니로 복사 $ scp ~/.codex/auth.json 맥미니:~/.codex/auth.json # 4. 맥미니 Hermes config.yaml 수정 model: default: "gpt-5.4" provider: "openai-codex" # 5. 테스트 $ hermes chat -q "hello" --provider openai-codex

토큰 갱신

access_token은 약 10일마다 만료된다. Hermes가 refresh_token으로 자동 갱신을 시도하지만, 실패하면 맥북에서 codex login 후 다시 scp하면 된다.

7번의 실패와 하나의 질문 전환. "어떻게 뚫을까"에서 "다른 길은 없을까"로.

결국 문제를 푼 건 기술력이 아니라 관점의 전환이었다. Claude의 벽을 넘으려고 할 게 아니라, 벽이 없는 다른 서비스를 찾으면 되는 거였다.

지금 이 순간에도 내 맥미니 위에서, gpt-5.4가 돌아가는 Hermes가 조용히 대기하고 있다.

이 글은 Claude Code (Opus 4.6) + Hermes Agent (gpt-5.4) 조합으로 작성되었습니다.
